Tutorial para principiantes

Así funciona lo que vas a construir: una base de datos real alimenta un panel web con propiedades, clientes y citas.

¿Qué vas a aprender aquí?

Vas a aprender a crear un panel CRM inmobiliario web con base de datos real usando herramientas de Inteligencia Artificial generativa de código. No necesitas saber programar: escribirás instrucciones en español (llamadas prompts) y la IA construirá la aplicación por ti.

En menos de una hora tendrás claro cómo pasar de una idea a un panel funcional con cuatro pantallas (Dashboard, Propiedades, Clientes y Calendario), autenticación de usuarios y datos que se guardan de verdad.

¿Para qué sirve un CRM inmobiliario?

🏢 Propiedades

Guardar cada inmueble con foto, precio, ubicación y descripción. Verlos en tarjetas y en vista detalle.

👥 Clientes

Tener una tabla con nombre, teléfono y email, más notas de seguimiento de cada comprador o vendedor.

📅 Citas

Agendar visitas en un calendario mensual vinculando un cliente concreto con una propiedad concreta.

📊 Dashboard

Ver de un vistazo cuántas propiedades activas tienes, cuántos clientes y qué citas hay hoy.

¿Por qué merece la pena aprenderlo?

  1. Ahorro masivo de dinero. Encargar este software a programadores tradicionales puede costar miles de dólares. Con IA consigues un prototipo funcional o una aplicación terminada sin coste inicial usando planes gratuitos.
  2. Velocidad de ejecución. En lugar de esperar semanas o meses, obtienes un panel web operando en minutos.
  3. Autonomía tecnológica. Profesionales independientes y pequeñas agencias pueden crear herramientas a medida sin depender de terceros.

Situaciones reales donde se utiliza

  • Agentes inmobiliarios independientes: necesitan registrar sus captaciones de viviendas y sus clientes sin pagar licencias mensuales elevadas.
  • Agencias inmobiliarias pequeñas: buscan modernizar su flujo de trabajo y visualizar las visitas en un calendario dinámico.
  • Emprendedores y desarrolladores No-Code: quieren prototipar rápido una aplicación web para validar una idea ante inversores o clientes.

Capítulo 1

Conceptos Fundamentales y Herramientas

Antes de escribir una sola letra en una plataforma de IA, necesitas dominar cuatro conceptos. Si los entiendes, todo lo demás sale solo.

1. CRM Inmobiliario

Un CRM inmobiliario (siglas inglesas de Customer Relationship Management, o Gestión de Relaciones con Clientes) es un sistema de software diseñado para organizar, automatizar y administrar todas las interacciones de un negocio inmobiliario.

Sirve para:

  • Gestionar las propiedades disponibles.
  • Dar seguimiento a clientes compradores o vendedores.
  • Coordinar citas en un calendario.
  • Guardar el historial de acuerdos en un solo lugar centralizado.

2. Base de Datos Relacional

Es la estructura interna donde se almacenan de forma organizada las tablas de información: propiedades, clientes, citas y usuarios. Cada tabla tiene columnas (campos) y filas (registros), y las tablas se relacionan entre sí (por ejemplo, una cita apunta a un cliente y a una propiedad).

3. Prompt

Un prompt es la instrucción escrita y detallada que le entregamos a la Inteligencia Artificial para que genere el software. Cuanto más concreta, mejor será el resultado.

4. Persistencia de Datos: la diferencia que lo cambia todo

TipoQué esQué pasa al cerrar la ventana
Datos hardcodeados / estáticos Datos fijos insertados dentro del código (por ejemplo, un archivo JSON estático). Se pierden. Si agregas un dato nuevo, no se guarda de forma duradera.
Base de datos real Estructura externa donde los registros se guardan permanentemente en servidores. Se conservan. Permite crear, consultar, actualizar y eliminar datos (operaciones CRUD).

Analogía cotidiana: el restaurante

Imagina que tu CRM es un restaurante:

  • La Interfaz Web (Frontend) son las mesas, el menú impreso y la decoración que ve el cliente.
  • La Base de Datos (Backend) es el almacén y la despensa donde se guardan organizadamente todos los ingredientes. Si no hay almacén real, las comidas del menú son de plástico (datos de demostración estáticos).
  • La IA (Moca o Gemini) es el cocinero experto que arma todo el restaurante siguiendo tus recetas escritas (el prompt).

Ejemplo correcto vs. incorrecto de Prompt

❌ Ejemplo incorrecto (vago e impreciso)

"Hazme una página web para vender casas y gestionar clientes."

¿Por qué es incorrecto? La IA no sabrá qué pantallas necesita, qué colores usar, ni qué campos requiere la base de datos, por lo que generará algo genérico e incompleto.

✔️ Ejemplo correcto (estructurado y accionable)

"Crea una aplicación web para un panel de CRM inmobiliario… Incluye 4 pantallas: Dashboard, Propiedades, Clientes y Calendario. Conecta una base de datos con 3 tablas principales (propiedades, clientes, citas) y datos de demostración."

¿Por qué funciona? Nombra las pantallas, los componentes, la base de datos y los datos demo. No deja nada a la imaginación de la IA.

Capítulo 3 — Construcción paso a paso en Moca (base de datos real)

Sigue esta secuencia numerada. Cada paso tiene una sola acción.

  1. Regístrate en Moca y obtén tus créditos de prueba.

    Entra en la web de Moca, pulsa el botón de registro y crea tu cuenta (puedes vincular tu cuenta de Google).

    Motivo: al registrarte, Moca asigna automáticamente 120 créditos de prueba gratuitos en el plan inicial (Free), lo que te permite probar la generación de software completo. Resultado esperado: ves tu panel principal con 120 créditos disponibles.
  2. Crea un nuevo proyecto e ingresa el Prompt Maestro.

    En el panel principal de Moca pulsa Create New y pega el Prompt Maestro en la casilla de texto principal. Pulsa ejecutar.

    Motivo: Moca procesará las instrucciones (normalmente con modelos de última generación como Claude Sonnet) para estructurar el código fuente y los esquemas de base de datos simultáneamente. Resultado esperado: la IA empieza a generar la aplicación y su backend.
  3. Supervisa la creación automática de la base de datos.

    Observa el panel de desarrollo mientras trabaja y haz clic en la pestaña Data del menú lateral.

    Verificación: comprueba que la IA haya creado automáticamente las 4 tablas necesarias: propiedades, clientes, citas y usuarios. Resultado esperado: ves las 4 tablas listadas con sus columnas. Motivo: a diferencia de otras plataformas, Moca lee la instrucción de persistencia y diseña la estructura relacional sin que tengas que configurar SQL a mano.
  4. Puebla el sistema con datos de demostración.

    Cuando Moca termine la primera versión visual, abre la vista previa a pantalla completa, pulsa Google Login e inicia sesión. En la pantalla inicial, pulsa Cargar datos de demostración.

    Verificación: navega a Data → propiedades y comprueba que los registros (títulos, precios, enlaces de fotos) aparecen guardados en la tabla. Resultado esperado: la tabla contiene inmuebles de muestra (por ejemplo, "Casa moderna en Las Condes") e información de clientes. Motivo: ese botón ejecuta una función interna que inserta los datos demo directamente en la base de datos real.
  5. Implementa formularios y operaciones CRUD avanzadas.

    Vuelve a la ventana de chat de Moca y envía este prompt de seguimiento:

    PROMPT DE SEGUIMIENTO

    Persistencia y CRUD en Base de Datos

    Descripción: activa la creación y edición de propiedades y clientes con modales integrados.

    Uso: envíalo como iteración después de tener el esqueleto del CRM generado.

    Permitir crear y editar propiedades y clientes. Implementa componentes modales elegantes que se integren perfectamente con el diseño actual.
    Motivo: la IA agregará las funciones de escritura (INSERT) y edición (UPDATE), incluyendo validaciones de campos como el formato de correo electrónico. Resultado esperado: prueba crear un nuevo cliente rellenando el formulario modal y comprueba que aparece en la tabla.
[Prompt Ejecutado] ──> [Tablas Creadas en 'Data'] ──> [Cargar Datos Demo] ──> [Registros Persistentes]
⚠️ Advertencia sobre consumo de créditos: las solicitudes complejas que integran base de datos consumen más créditos de procesamiento. Al completar el prompt inicial y la adición de formularios CRUD, es normal agotar los 120 créditos gratuitos de prueba (quedando en 0 créditos).
💡 Cómo evitar fallos al guardar datos: si al enviar un formulario (por ejemplo, agregar una propiedad) notas que no se guarda en la base de datos, puede deberse a que la generación consumió el límite de créditos antes de terminar la conexión backend. Revisa siempre que la validación del formulario esté completa.

Capítulo 4 — Prototipado en Google AI Studio y Restore Checkpoint

Si prefieres diseñar un prototipo estático, rápido e ilimitado, Google AI Studio es la herramienta ideal.

  1. Configura el entorno en Google AI Studio.

    Entra en Google AI Studio con tu cuenta de Google, selecciona el modelo Gemini, pega el Prompt Maestro en la ventana principal de comandos y pulsa Run.

    Motivo: Gemini generará la aplicación web completa en formato de prototipo estático interactivo. Resultado esperado: aparece una previsualización con la interfaz del CRM.
  2. Corrige el idioma.

    Si el prototipo aparece en inglés, escribe en el chat:

    PROMPT DE LOCALIZACIÓN

    Traducción y Localización al Español

    Descripción: fuerza a que toda la interfaz aparezca en idioma español.

    Uso: úsalo cuando la IA genere textos por defecto en inglés.

    Todo texto debe aparecer en español.
    Resultado esperado: toda la interfaz pasa a español.
  3. Afinar la interfaz para que los formularios se vean terminados.

    Envía este segundo comando:

    PROMPT DE UI

    Completado y Navegabilidad de Formularios

    Descripción: completa los formularios y modales para que se vean terminados y sean navegables.

    Uso: úsalo cuando los botones de acción rápida no abran los modales completos.

    Los formularios de añadir propiedad, cliente y cita: completa el diseño para que se vean terminados y sean navegables.
    Motivo: Google AI Studio actualizará el código usando datos estáticos en formato JSON para simular el comportamiento de la plataforma. Resultado esperado: los botones y formularios responden visualmente aunque no guarden datos.
  4. Si algo se rompe, usa Restore Checkpoint.

    Si al enviar una nueva orden la IA comete un error, borra elementos visuales o rompe la aplicación, busca en la barra superior el botón Restore Checkpoint y pulsa.

    Motivo: te evita perder el trabajo realizado y permite corregir la instrucción sin empezar desde cero. Resultado esperado: vuelves exactamente a la versión que funcionaba antes del prompt erróneo.

Resumen del Capítulo 4

  • Google AI Studio con Gemini es perfecto para prototipado ágil y diseño UI/UX.
  • Utiliza archivos JSON estáticos para mostrar datos sin requerir servidor.
  • La herramienta Restore Checkpoint es la mejor salvaguarda para revertir fallos de generación.

Ejercicio 2 — Restaurar una versión dañada

Consigna: le pediste a Google AI Studio un cambio de diseño, pero eliminó la pantalla del calendario.

Ver solución explicada
  1. Dirígete a la parte superior de Google AI Studio.
  2. Haz clic en el botón Restore Checkpoint.
  3. Comprueba que el calendario vuelve a aparecer.
  4. Vuelve a escribir tu petición de diseño, pero esta vez sé más específico: "Cambia solo los colores de las tarjetas del Dashboard. No modifiques ninguna otra pantalla."

Razón: esto revertirá el código al estado exacto previo a la instrucción errónea, sin perder el trabajo anterior.

Ejercicio 3 — Conseguir que los formularios se vean terminados

Consigna: en el prototipo de Google AI Studio, los formularios se ven a medias y no se pueden navegar.

Ver solución explicada
  1. Abre el chat de Google AI Studio.
  2. Pega este prompt de seguimiento: 
    Los formularios de añadir propiedad, cliente y cita: completa el diseño para que se vean terminados y sean navegables.
  3. Prueba a abrir cada formulario y a cerrarlo.

Razón: Google AI Studio usará datos estáticos en formato JSON para simular el comportamiento, así que los formularios se verán y se navegarán bien, pero no guardarán datos. Eso es esperado en esta herramienta.

Ejercicio 4 — Elegir la herramienta correcta

Consigna: necesitas presentar mañana una demo a un inversor y, por separado, necesitas un CRM que use tu agencia a diario.

Ver solución explicada
  • Para la demo de mañana: Google AI Studio con Gemini. Es gratuito, rápido e ilimitado para prototipos visuales y la interfaz se ve muy bien.
  • Para el uso diario de la agencia: Moca. Necesitas persistencia real: que los clientes y las citas se guarden al cerrar la ventana, y que exista autenticación de usuarios de verdad.

Razón: la diferencia clave es si los datos deben sobrevivir al cierre de la pestaña o no.

Preguntas frecuentes (FAQ)

1. ¿Necesito saber programar en HTML, CSS o SQL para usar este tutorial?

No. No necesitas ningún conocimiento previo de programación. Todas las estructuras, estilos y tablas de la base de datos son creadas automáticamente por la IA a partir de las instrucciones escritas en español.

2. ¿Qué diferencia hay entre Google AI Studio y Moca?

Google AI Studio crea prototipos visuales con datos simulados (JSON), mientras que Moca integra una base de datos real donde la información ingresada se guarda de manera permanente.

3. ¿Qué hago si la IA genera el panel en inglés?

Simplemente envía un prompt corto diciendo: "Todo texto debe aparecer en español".

4. ¿Qué hago si la IA comete un error y borra parte de mi aplicación?

En Google AI Studio, utiliza el botón Restore Checkpoint para volver inmediatamente a la versión anterior que funcionaba bien.

5. ¿Cuánto tarda todo el proceso?

El prototipo visual puede estar listo en minutos. La versión con base de datos real, autenticación y datos demo suele quedar operativa en una sola sesión de trabajo. Lo que más tiempo consume es afinar la interfaz con prompts de seguimiento.

6. ¿Puedo usar el CRM en el móvil?

Sí. El Prompt Maestro incluye la instrucción "Totalmente responsive", lo que obliga a la IA a adaptar el diseño a pantallas de celulares, tablets y ordenadores.

Atención

Errores Frecuentes y Cómo Corregirlos

Errores que nunca deben cometerse

❌ 1. Escribir prompts imprecisos

Decir "haz una web de casas" sin detallar pantallas, campos ni colores genera aplicaciones incompletas.

Cómo corregirlo: usa siempre el Prompt Maestro de dos etapas (Diseño + Base de Datos) y nombra cada pantalla, cada campo y cada color en hexadecimal.

❌ 2. Olvidar pedir persistencia

No especificar "todos los datos desde la base de datos (nada hardcodeado)" provocará que la IA use datos falsos que no se guardan.

Cómo corregirlo: añade esa frase literal al final de tu prompt y verifica en la pestaña Data que las tablas existen de verdad.

❌ 3. Agotar créditos en solicitudes vagas

Hacer peticiones gigantescas sin medir los créditos de la plataforma te deja sin margen para las correcciones.

Cómo corregirlo: itera por etapas. Primero el diseño básico, luego las funcionalidades avanzadas. Y comprueba en la pestaña Data después de cada etapa.

❌ 4. Reiniciar desde cero ante un fallo

Olvidar usar la herramienta Restore Checkpoint cuando la IA falla hace que pierdas todo el trabajo previo.

Cómo corregirlo: ante cualquier destrozo visual, pulsa Restore Checkpoint y luego reformula la instrucción de forma más concreta.

  • Aprendiste qué es un CRM Inmobiliario y cómo organiza el trabajo diario con las pantallas de Dashboard, Propiedades, Clientes y Calendario.
  • Comprendiste la diferencia fundamental entre datos estáticos (JSON) y una base de datos relacional real.
  • Diseñaste un Prompt Maestro profesional que incluye detalles de UI/UX, navegación y persistencia.
  • Construiste un panel CRM web funcional en Moca con base de datos, autenticación Google y carga automática de datos demo.
  • Aprendiste a prototipar en Google AI Studio y a proteger tu trabajo utilizando Restore Checkpoint.

Recomendaciones para seguir aprendiendo

  1. Itera por etapas.Primero genera el diseño básico (Etapa 1) y luego añade funcionalidades avanzadas (Etapa 2).
  2. Explora componentes modales.Pide a la IA que cree vistas en ventana emergente (modal) para agilizar la navegación de tus usuarios.
  3. Analiza siempre la pestaña Data.Revisa el esquema de base de datos generado para asegurarte de que los campos coincidan con tu negocio.
  4. Guarda un checkpoint mental antes de cada cambio grande.Si el cambio rompe algo, sabrás exactamente a qué versión volver.

PROMPT 1

Arquitectura, Diseño y Estructura Inicial del CRM Inmobiliario

Descripción: prompt maestro que define en una sola instrucción los cimientos del sistema: distribución visual (UI), navegación (UX), paleta de colores corporativos con códigos hexadecimales exactos, las cuatro pantallas principales (Dashboard, Propiedades, Clientes y Calendario) y la estructura de tablas relacionales.

Uso: úsalo al inicio del proyecto como primera interacción con la IA (Moca o Google AI Studio). Su instrucción de "nada hardcodeado" obliga a la herramienta a desacoplar la interfaz del contenido y generar tablas reales de base de datos. 

Crea una aplicación web para un panel de CRM inmobiliario. La aplicación debe ser visualmente atractiva, moderna y con diseño de alta calidad.

PRIMERA ETAPA - DISEÑO Y NAVEGABILIDAD

Pantallas esenciales:

1. Dashboard Simple
- Contador de propiedades activas
- Contador de clientes
- Lista de citas de hoy
- Acceso rápido a agregar propiedad/cliente

2. Propiedades
- Listado en cards con foto, precio y ubicación
- Formulario para agregar propiedad (campos básicos: título, precio, ubicación, fotos, descripción)
- Vista detalle con galería y datos básicos

3. Clientes
- Tabla simple con nombre, teléfono, email
- Formulario para agregar cliente
- Vista de detalle con notas

4. Calendario
- Vista mensual de citas
- Modal para crear cita vinculando cliente y propiedad

Diseño:
- Navegación lateral simple con 4 opciones e iconos profesionales
- Colores: fondo blanco, azul primario (#2563EB), gris para textos (#64748B), verde (#16A34A) para acciones positivas y estados de éxito
- Totalmente responsive

BASE DE DATOS
- 3 tablas básicas: propiedades, clientes, citas
- Autenticación simple email/password
- CRUD básico
- Subida de imágenes

Datos de demostración:
- Generar set completo de datos demo
- Todos los datos desde la base de datos (nada hardcodeado)
PROMPT 2

Traducción y Localización de la Interfaz al Español

Descripción: prompt corto de localización que corrige el idioma de la aplicación cuando los modelos de lenguaje generan por defecto etiquetas, encabezados, botones o elementos del menú en inglés durante la maquetación inicial.

Uso: úsalo como iteración después del Prompt 1, si observas términos como "Properties", "Customers" o "Add New". Se envía en el mismo hilo de chat sin necesidad de rehacer el proyecto. 

todo texto debe aparecer en español
PROMPT 3

Completado y Navegabilidad de Formularios (Prototipado UI)

Descripción: prompt de maquetación detallada e interconectividad visual. En prototipos iniciales la IA suele generar botones de "Agregar propiedad" o "Nuevo cliente" sin crear los modales completos ni conectar sus eventos de apertura. Este prompt obliga al modelo a desarrollar la totalidad de los componentes de entrada de datos para que la experiencia de usuario sea totalmente funcional a nivel de prototipo navegable.

Uso: envíalo cuando, al hacer clic en los botones de acción rápida, no se desplieguen las ventanas flotantes o los formularios estén a medias. Se aplica igual en Google AI Studio y en Moca. 

los formularios de añadir propiedad cliente todos los tipos (cita etcétera) completa el diseño que se vean terminados y que sean navegables
PROMPT 4

Persistencia y Funcionalidad CRUD en Base de Datos

Descripción: prompt que convierte un prototipo estático en una aplicación dinámicamente funcional con operaciones CRUD (Crear, Leer, Actualizar y Eliminar). Ordena a la IA crear las rutinas de conexión entre los formularios del frontend y la base de datos real, permitiendo enviar datos mediante peticiones de inserción, validar campos obligatorios (por ejemplo, formato de correo electrónico) e insertar nuevos registros dinámicamente en las tablas.

Uso: envíalo cuando ya tengas el esqueleto del CRM generado y quieras activar la escritura y edición de datos. Requiere estar en una plataforma con soporte de base de datos real (como Moca). Tras ejecutarlo, verifica en la pestaña Data que los registros se insertan correctamente.

implementar los formularios para crear editar propiedades y clientes crearía componentes modales elegantes que se integren perfectamente con el diseño actual y permitan gestionar toda la información de manera intuitiva
